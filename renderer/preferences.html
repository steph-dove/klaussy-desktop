AI CLIs
Ollama serves local models a 4096-token window by default, which an agent's prompt and tool definitions alone exceed — so it loses its tools and forgets the conversation. Klaussy raises this on the model itself. Bigger windows hold longer sessions but reserve more memory up front, and are capped at what the model supports.

Slack & Discord Notifications
Post to a chat channel when an agent finishes, fails, or stops to ask for permission — so you can leave Klaussy in the background. Paste a webhook URL for either service (or both). Leaving both empty turns the whole feature off.
Anyone who can read this machine's config file can read these URLs, and anyone holding one can post to that channel. Prefer a webhook scoped to a channel you don't mind that for.
Posts each thing the agent says into that session's thread as it happens, so you can follow along and answer by replying — rather than only hearing about it when Klaussy recognises a prompt. Turning this off falls back to the quiet alert below.
For when an agent stops without asking anything — usually output waiting to be read. Kept separate from the 15-second desktop idle notification, which is far too frequent for a chat channel.

Replying from chat (optional)
A webhook only sends one way. To get Approve/Reject buttons and to answer an agent by typing in the channel, Klaussy needs a Slack app or Discord bot — it opens an outgoing connection, so there's no public URL or tunnel involved. Step-by-step setup guide ↗
Read before enabling: anyone you allow below can approve a permission prompt on this machine — including an agent asking to run something destructive. Use a private channel. Approvals are single-use and expire after 30 minutes.
Slack — create an app, turn on Socket Mode and Interactivity, add the chat:write and channels:history scopes, then /invite the bot to the channel. Slack setup steps ↗
Discord — create a bot, turn on the Message Content intent, and invite it with permission to read, post and create threads. Discord setup steps ↗
Slack member IDs and/or Discord user IDs. Leaving this empty means nobody can approve from chat — the buttons will refuse every click.
Git
Seconds between background fetches. Set to 0 to disable.
Before a commit lands (Klaussy's Commit button and a git pre-commit hook in session repos), your agent reviews the staged diff for silent failures, leaked secrets, debug leftovers, and blatant correctness landmines, and your repo's linter runs on the staged files. You always decide: fix or commit anyway. Unchecking removes the git hooks.
Right before a commit, your agent tightens the comments it added so they stay short: regular comments to at most two sentences (ideally one), docstrings to at most five — and deletes ones that just restate the code. It only touches comments on the lines you're committing, never your code, and leaves license headers and pragmas (eslint-disable, @ts-ignore, TODOs) alone. Runs through the same pre-commit hook. On by default; uncheck to leave comments as written.
When generating repo intelligence for a new repo, run your agent to rewrite CLAUDE.md into richer prose. This makes an API call (billed to your agent account) on your machine. Off by default — the conventions, rules, skills, and import graph are still generated either way.
